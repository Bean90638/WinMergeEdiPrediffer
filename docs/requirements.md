# 開發需求與驗收條件

## 規則組管理

- 可新增、複製、重新命名、啟用／停用、刪除多個組。
- 每組可設定完整檔案路徑與檔名的正則，初始值為 `.*`。
- 組依畫面由上往下比對，只使用第一個命中的啟用組；取消數字優先序與預設組勾選。
- 組與規則均可拖曳最左側列首排序，保留啟用勾選；路徑 `.*` 的兜底組由使用者放最後。
- 舊 Schema 1 設定載入時依原優先序及預設組位置轉成 Schema 2 排列；後續儲存與載入不再重排。
- 同時命中多個組時可查看命中結果及實際選定的組。
- 設定檔支援儲存、載入、匯入與匯出。

## 組內規則管理

- 每組可新增、複製、重新命名、刪除多條規則。
- 可調整規則順序及個別啟用／停用。
- 可設定尋找文字／正則、取代文字、大小寫條件。
- 設定視窗輸入單層正則；JSON 跳脫由程式處理。
- 表格複製只輸出目前儲存格的純文字，不含整列、標題或 HTML 表格。
- 顯示錯誤規則的位置與原因，錯誤設定不產生可安裝外掛。

## 預覽與 WinMerge 整合

- 輸入測試路徑，顯示命中規則組。
- 輸入 EDI 文字，顯示逐條規則的替換結果。
- 內容正則預覽與 COM DLL 共用 C#/.NET 規則引擎，逐行取代並保留 CR/LF。
- 路徑與內容正則使用 C#/.NET；選組路徑由 WinMerge 修正版的 PluginOriginalFilePath 提供；PluginVariables 保持既有處理路徑語意，須實測來源與暫存路徑。
- 只有一個固定 C# COM host；在 C# 內選組，每次呼叫讀取已套用的共用 JSON。
- 安裝僅管理本工具產生的外掛，保留既有外掛與 EDI。
- 內容規則改動可在 WinMerge 開啟時套用，管理器通知刷新目前比對分頁。
- 新增／刪除組、路徑／排列順序／啟用狀態只發布 JSON，不重新讀取外掛或重設自動選組。
- 自動通知限定 WinMerge 2.16.58.2，其他版本提示手動 F5。
- 擴充功能視窗開著時亦可發布與要求刷新；以同一程序、視窗及比對結果驗證，不以訊息送出當成完成。
- 多分頁時刷新作用中的比對，其餘分頁在切換後可用 F5 讀取最新設定。
- 固定外掛資訊不隨組變動，刪除組不產生殘留 DLL；首次升級或部署檔修復才要求關閉。

## 必要驗收案例

- 850 與 860 檔案自動選用各自的規則組。
- 組內兩條以上規則均按序生效。
- 未命中專屬組時套用放在最後的 `.*` 兜底組；若拖到前面，依顯示順序先命中。
- 組與規則向上／向下拖曳後保留所選項目，儲存重開仍依相同順序選組與執行。
- 停用組或規則時，其內容不再影響比對。
- 同一檔名位於不同目錄時，可依完整路徑選用不同組。
- `old` 與 `new` 對應檔案都能命中預期組。
- 忽略 ST02 但保留 ST01，因此 850 與 860 仍有差異。
- SE02 只有在使用者另外設定對應規則時才忽略。
- 資料夾比對、檔案比對、重新掃描的結果一致。
- 行數、原始檔案內容與 SHA-256 保持不變。
- 鎖住 DLL、配套及固定 profile，保持同一原生 COM 物件；多組更新後讀到新規則，固定檔案及時間戳不變。
- 儲存原始 JSON 不等同發布；無效套用不影響最後一次有效設定。
- 保持同一個 WinMerge 程序及資料夾比對分頁，啟用組、多條規則及路徑正則變動後，介面的比對結果自動更新。

## 原始路徑傳遞修正

- WinMerge 2.16.58.2 修補以選用屬性提供各側解包前原始路徑，不修改既有 PluginVariables。
- Router 每次呼叫消耗並清除來源狀態；缺少新屬性須明確報錯，不可用暫存路徑默默選預設組。
- 未儲存的新文件由 host 明確提供空來源，保留內容且不套用路徑組。
- 管理器套用前檢查 WinMerge 配套與執行中的程序，檢查失敗不保存或部署設定。
- 可開啟路徑診斷，記錄兩份路徑、選組、原因及設定指紋，不記錄 EDI 內容，診斷失敗不影響比對。
- 真正的 WinMerge 執行檔驗證須同時覆蓋資料夾比對及單檔的編輯器暫存流程，確認輸出報告與原始 SHA-256。
